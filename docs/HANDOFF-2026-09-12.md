## 2. What the product is

Concierge shopping for Ghana: a customer pastes a US/UK/China store link, sees a landed GH₵ price,
pays in full (Paystack), Tomame buys and delivers. Next.js 16 App Router, Supabase (Postgres +
Auth + RLS), Paystack, Resend, deployed on **Vercel Pro**. Money maths and every state transition
are server-side; `audit_logs` is append-only.

Authoritative specs: `agent.md`, `FEATURES.md`, `system-flow.md`. Redesign contract:
`docs/redesign-data-map.md` (element → table/endpoint, with file:line citations) and
`docs/redesign-icon-map.md`. Mocks: `design/*.dc.html` (plain HTML, every value literal);
pre-flattened artboards in `design/_render/`.

## 4. Decisions Kelvin has approved (do not reopen)

Phase 3, approved 2026-09-12 before code:
1. **Lock scope = FX only.** Item price is re-read live at order time. **Customer pays the lower of
   locked and live**: the lock ratchets down, never up, so what is shown and what is charged agree.
   The lock's `pricing` JSONB is an informational snapshot, **never a price source** (a review found
   the preview's client gap-filler `itemPriceUsd` could leak into it — fixed in §7).
2. **Anonymous quotes**: server-minted httpOnly cookie, adopted onto the user on the first signed-in
   request. The client never sends a rate or lock id; the server resolves the lock by
   (viewer, extraction_cache_id).
3. **Tax stays blended 10%**, labelled from the live constant. Per-state tax is not a Phase 3 item:
   tax is charged at Tomame's US receiving address, so the Fees page line "varies by US state" is the
   copy that is wrong (Phase 1 copy fix).
4. **Fee stays tiered 4–8%**, labelled from the live percentage. "From 4%" marketing copy is a Phase 1 edit.
5. **"Door delivery · Accra — Free"** renders from the default door zone; if its fee becomes non-zero
   the row reads "from GH₵X, chosen at checkout" and the total stays ex-delivery. No
   `delivery_fee_ghs` until Phase 4.
6. **"Describe it" stays out** of the paste bar (needs its own intake; the catalogue search above is
   the beginning of that path).
Also agreed: primary CTA on the quote is the existing order submission labelled **"Continue to
payment"** until the bag exists (Phase 4); mobile **keeps the quantity stepper and the lock line**
even though artboard 2 omits them; **no colour swatches** (colour-name → hex would be invented).

Earlier decisions (see `phase-2-handoff.md` §8, `project` memory): Paystack-branded single button;
only the USA is purchasable (UK/China disabled with waitlist); stage word "Purchased"; GH₵ first,
$ second; Phosphor icons from `@phosphor-icons/react/ssr`, never `lucide-react` in new code; keep
`--tm-coral #F25B3D` even though the logo is `#F85000`.

Infrastructure decision (2026-09-12): **background work = Supabase pg_cron → pg_net GET → Vercel
route with `Bearer CRON_SECRET`.** No workers, no Vercel Cron, no queues. Jobs are small idempotent
batches fired often (one vendor call per run, < 60 s) because Vercel Pro caps a function at 300 s.
The price-watch job (200 watches per run) should be retrofitted to that shape.

## 7. Review fixes applied 2026-09-12 — verified in code and by curl, but re-check before F3

A seven-angle code review of F1 + F2 produced ten confirmed findings. All ten were applied and
verified (grep + gates + curl against the dev server) before this session ended; `quote_locks` was
left empty and the USD rate restored to exactly 14.430000. What each fix is, so you can confirm:

1. `order-intake.service.ts` — the branch that used `lock.pricing.item_price_usd` as a trusted price
   must be **gone**; gap-filler eligibility (`gapFillOverrides`) lives in `quote.service.ts`, not the
   preview route.
2. `calculator.ts` — `FxOverride` must carry `cross_rates` (from the lock's new `fx_rates` column);
   `toUsd` under a lock uses the snapshot cross rate and throws 503 if the currency is absent;
   `priceUnderLock` compares **totals** (lower `total_ghs` wins), not just the USD pair.
3. `orders.review.service.ts` — admin re-price applies the lock only if unexpired **and** lower.
4. `quote-locks.ts` `findActiveLock` by session adds `.is("user_id", null)`.
5. `buildOrderIntake` degrades to live pricing on transient lock errors (rethrows schema-missing and
   `QuoteConstantsMissingError`).
6. `ratchetLockRate` has a `.gt("exchange_rate", …)` guard; `consumeLock` guards on
   `consumed_by_order_id IS NULL`; `consumeActiveLocks` marks sibling locks; adoption only runs when
   the user lookup misses.
7. `isWatching` degrades to `false` on non-schema errors.
8. `extraction-cache.ts` getters apply `withProductDefaults` in the row mapping.
9. Missing seeded constants throw `QuoteConstantsMissingError` and are rethrown (fail loudly).
10. Home receipt (`home.service.ts`) prices under the viewer's **existing** lock, never mints.
Plus cleanups: `priceLive` removed; one `cleanTitle` in `scrapers/parse.ts`; `where-we-buy` uses
`pickDefaultDoorZone`; `parseRating` prefers "x out of 5"; calculator loaded once per request.
Migration 044 was edited in place (unreleased) to add `fx_rates`; the local column was added by hand.

**Re-verified 2026-09-12 (session 2), file by file: all ten fixes are applied.** Three corrections
to the prose above, which described the fixes from memory:
